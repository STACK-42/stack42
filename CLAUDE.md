## Project

stack42's marketing site — a single-page landing page (`/`) built with TanStack Start. Originally scaffolded and still synced with [Lovable](https://lovable.dev).

> [!IMPORTANT]
> This project is connected to Lovable. Avoid rewriting published git history — force pushing, or rebasing/amending/squashing commits already pushed — since it rewrites history on Lovable's side and the user will likely lose project history. Commits pushed to the connected branch sync back into the Lovable editor, so keep the branch in a working state.

## Commands

This project uses **bun** (see `bun.lock`, `bunfig.toml`).

- `bun install` — install dependencies
- `bun run dev` — start dev server (vite dev)
- `bun run build` — production build
- `bun run build:dev` — build in development mode
- `bun run preview` — preview a production build
- `bun run lint` — eslint over the whole repo
- `bun run format` — prettier --write over the whole repo

There is no test suite/runner configured in this repo currently.

`bunfig.toml` enforces a 24h supply-chain guard (`minimumReleaseAge`) on new dependency versions; only a short allowlist of `@lovable.dev/*` packages bypasses it. Don't add packages to that exclusion list without the user's explicit confirmation.

## Architecture

**Stack**: TanStack Start (file-based SSR React framework, v1) + TanStack Router + TanStack Query, Tailwind v4, shadcn/ui (Radix primitives) components, React 19, Vite 8, Nitro (build-time server target).

### Vite config is mostly hidden

`vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`, which already registers TanStack devtools, `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, the `@` path alias, React/TanStack dedupe, error-logger plugins, and sandbox port/host detection. **Do not re-add any of these plugins manually** — duplicates will break the app. Only pass extra config through `defineConfig({ vite: {...}, tanstackStart: {...} })`.

### Routing (`src/routes/`)

File-based routing via TanStack Router — see `src/routes/README.md` for the full convention table (dynamic `$id`, optional `{-$category}`, splat `$.tsx`, `_layout.tsx`, etc). Key points:
- Do **not** create `src/pages/`, `app/layout.tsx`, or Next/Remix-style route folders — those conventions don't apply here.
- `src/routes/__root.tsx` is the only root layout/app shell; it must keep `<Outlet />` or all child routes break.
- `src/routeTree.gen.ts` is auto-generated by the TanStack router plugin — never hand-edit it.
- `src/router.tsx` creates the router with a `QueryClient` in context and `defaultPreloadStaleTime: 0`.

### SSR error handling (custom, layered)

This app has a deliberate multi-layer defense against SSR errors rendering as a blank/broken page, because h3 (Nitro's HTTP layer) swallows in-handler throws into a generic `{"unhandled":true,"message":"HTTPError"}` 500 response, discarding the stack:

1. `src/lib/error-capture.ts` monkey-patches `console.error` and window `error`/`unhandledrejection` listeners to record the last real `Error` object (5s TTL) so it can be recovered later, and expands Error/cause chains into full text before they reach logs.
2. `src/start.ts` defines `errorMiddleware`, wrapping every server request/server-fn call to catch real errors and return a static HTML error page (`src/lib/error-page.ts`) instead of letting them surface as raw JSON. It also re-declares `createCsrfMiddleware` — TanStack Start only auto-installs CSRF protection on server functions when `src/start.ts` is *absent*, so defining this file requires manually re-adding it (already done — don't remove it).
3. `src/server.ts` wraps the generated Nitro/Start server entry (`@tanstack/react-start/server-entry`) and additionally detects the h3-swallowed-500 case specifically (JSON body with `unhandled: true`), pulling the real captured error back out via `consumeLastCapturedError()` before rendering the same static error page.
4. `src/routes/__root.tsx` provides client-side `notFoundComponent` and `errorComponent` (React error boundary equivalent for routes), which also forward to `reportLovableError` (`src/lib/lovable-error-reporting.ts`) — a no-op outside the Lovable editor preview, where it feeds the editor's telemetry/error console.

When touching server entry, middleware, or root-level error UI, preserve this chain — each layer exists to catch a specific failure mode the others miss.

### UI components (`src/components/ui/`)

Full shadcn/ui set (Radix-based) generated via `components.json` (`style: "new-york"`, base color slate, CSS variables, no prefix). Import via the `@/` alias (`@/components/ui/...`, `@/lib/...`, `@/hooks/...` — see `tsconfig.json` paths and `components.json` aliases). Regenerate/add components with the standard shadcn CLI rather than hand-rolling new primitives.

### Design tokens

Custom color tokens defined in `src/styles.css` and used throughout instead of default Tailwind palette names: `paper` (bg), `ink` (text), `graphite` (muted text), `hairline` (borders), `signal` (accent/brand green). Fonts are Inter (sans) and JetBrains Mono (mono, used for the wordmark/labels), loaded via Google Fonts `<link>` tags in `__root.tsx`'s `head()`.

### Linting/formatting

- ESLint (`eslint.config.js`) bans importing the `server-only` npm package — TanStack Start doesn't use it; rename modules to `*.server.ts` or use `@tanstack/react-start/server-only` instead.
- Prettier is run as an ESLint rule (`eslint-plugin-prettier/recommended`), so `bun run lint` and `bun run format` should agree. Config: 100 print width, double quotes, trailing commas everywhere.
- `noUnusedLocals`/`noUnusedParameters` are off in `tsconfig.json`, but most other strict flags are on (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitReturns`, etc).
